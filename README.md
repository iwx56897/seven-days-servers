## 开服前的三个前提：版本、系统、内存

三个前提里，任何一个判断错，后面都得返工。服务端程序是同一个（Steam 上的 app id `294420`），但装在哪、叫什么名字、吃多少内存，取决于你的选择。

**版本决定目录名。** A21 及更早的版本，服务端解压后是 `7DaysToDieServer`；1.0 正式版之后改成了 `7 Days to Die Dedicated Server`。网上两套路径教程同时存在，原因就在这里。不用记哪个对应哪版，直接看 `steamapps/common` 下面实际生成的是哪个文件夹，照着进就行。

**系统决定操作方式。** Windows 全程图形界面，改配置用记事本，启动双击 `.bat`，第一次接触服务器的人不容易迷路；代价是桌面环境本身要占内存和硬盘。Linux 没有这些额外开销，同样的预算能买到更多内存，但装 SteamCMD、开 screen、改防火墙都得敲命令。

**内存决定能不能启动。** 腾讯云开发者社区的七日杀搭建教程里给出的下限是 2 核 4G。低于 4G 的机器在 Linux 下几乎一定会遇到服务端进程刚跑起来就被系统杀掉的情况，因为七日杀生成地图那一下的内存峰值不低。这种情况得先配 swap 再谈启动。

## Windows 路线：远程桌面 + SteamCMD

Windows 这条路线适合第一次开服的人，全程有界面可看，出错了也容易发现是哪一步不对。

1. **连上服务器。** 本机搜索“远程桌面连接”（或运行 `mstsc`），计算机填公网 IP，用户名一般是 `Administrator`，密码在控制台复制。第一次连接会有证书提示，跳过即可。
2. **建目录。** 在 C 盘新建 `C:\7days`。路径里不要有中文和空格，否则 SteamCMD 会报一些很难看懂的错。
3. **下载 SteamCMD。** 在服务器浏览器里搜 SteamCMD 官方下载页，拿到 zip 后解压到 `C:\7days`。
4. **拉服务端。** 在 `C:\7days` 文件夹里按住 Shift 再点右键，选“在此处打开 PowerShell 窗口”，执行：
   
   ./steamcmd.exe +login anonymous +app_update 294420 validate +quit
   
   服务端有十几个 G，下载时间看机房带宽。中途失败就重新执行一次，这条命令带 `validate`，重复跑不会把文件搞坏。看到 `Success` 就完成了。
5. **改 platform.cfg。** 进 `C:\7days\steamapps\common\7 Days to Die Dedicated Server`，用记事本打开 `platform.cfg`，删掉第二行的 `crossplatform=EOS`，保存。
6. **改 serverconfig.xml。** 下面单独讲。
7. **启动。** 双击目录里的 `startdedicated.bat`。正常情况会弹出两个窗口，第一次启动要生成地图，等几分钟。如果只弹出一个窗口，基本可以确定是 `serverconfig.xml` 里某处格式写错了，回去逐行检查标签有没有闭合。

关服务器时别直接点窗口右上角的叉，那样进程还在后台跑。用任务管理器找到七日杀的服务端进程结束掉，再重启才干净。

## Linux 路线：Ubuntu + screen

Linux 这条路线的优势在内存利用率，同样 4G 内存，Ubuntu Server 比 Windows Server 能多留出不少给服务端。

以 Ubuntu 为例，先补依赖再装 SteamCMD：

bash
sudo dpkg --add-architecture i386
sudo apt update
sudo apt install steamcmd


如果提示找不到包，先确认 `/etc/apt/sources.list` 里启用了 `multiverse` 源。

然后拉服务端：

bash
steamcmd
login anonymous
force_install_dir ~/7DaysToDieServer
app_update 294420 validate
exit


`force_install_dir` 这一步是可选的，但建议加，它把安装位置固定下来，以后更新时不会因为版本改了目录名而找不到文件。

启动前先开一个 screen，避免 SSH 断线把服务端一起带走：

bash
screen -S 7days
./startserver.sh -configfile=serverconfig.xml


服务端跑起来之后按 `Ctrl+A` 再按 `D`，会话转入后台。要回控制台看日志用 `screen -r 7days`，停服就在会话里按 `Ctrl+C`。

内存小于 4G 的机器，先加 swap 再启动，否则大概率在生成地图那一步被 OOM killer 干掉：

bash
sudo fallocate -l 8G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile


最后把 `/swapfile swap swap sw 0 0` 写进 `/etc/fstab`，重启后才不会失效。

## serverconfig.xml：真正需要动的就这几行

这个文件有上百行，第一次打开容易被吓到。实际必改的只有服务器标识、地区语言、端口和存档位置，其余都能用默认值先跑起来。

| 配置项 | 建议值 | 说明 |
| --- | --- | --- |
| `ServerName` | 自定义 | 服务器列表里显示的名字 |
| `ServerPassword` | 自定义或留空 | 留空就是不设密码 |
| `Region` | `Asia` | 影响游戏内搜索时的地区归类 |
| `Language` | `Chinese` | 影响搜索归类，不改变游戏内实际语言 |
| `ServerPort` | `26900` | NAT 环境下要改成映射出去的那个端口 |
| `ServerMaxPlayerCount` | 按配置定 | 默认 8 人 |
| `EACEnabled` | `false` | 只有装 Mod 时才需要关 |
| `UserDataFolder` / `SaveGameFolder` | 自定义路径 | 默认是注释状态，要手动去掉注释符 |

存档这两行有坑：它们默认被 `<!-- -->` 包着，光改路径不删注释符等于没改。路径最后记得带反斜杠（Windows）或斜杠（Linux）。

另外，如果朋友在服务器列表里搜不到、直连也进不去，可以试试把 `ServerDisabledNetworkProtocols` 那一行里列出的 `SteamNetworking` 去掉，这在 1.0 之后的版本里是比较常见的一个连接问题来源。

## 端口放不通，前面全白做

**只开 26900 一个 UDP 端口是不够的**，管理功能和客户端的部分通信会走别的端口。七日杀服务端涉及的端口大致是这样：

| 端口 | 协议 | 用途 |
| --- | --- | --- |
| 26900～26902 | UDP | 游戏主端口与客户端通信 |
| 8080 | TCP | 远程 Web 控制台，不用可以不开 |
| 8081 | TCP | Telnet 管理端口，建议只在本机连 |
| 8082 | TCP | 服务器管理工具端口 |

云服务器上要过两道关：控制台的安全组规则，和系统自带的防火墙。很多人只改了其中一边，然后在论坛上问“为什么端口开了还是连不上”。Ubuntu 上用 `sudo ufw status` 看一眼状态，Windows 上检查“高级安全 Windows Defender 防火墙”的入站规则，两边都放通了才算数。

## 朋友进服与连不上时的排查顺序

进服本身很简单：游戏主界面点“加入游戏”，选下面的“连接至 IP”，填 `公网IP:26900`，几秒后就能进去。进不去的话，按下面的顺序排查，基本能定位到问题。

1. **“加入游戏”按钮是灰的。** 这是客户端没连上 Steam 服务，先开加速器再启动游戏。
2. **服务器启动后立刻连。** 第一次启动要生成地图，控制台还在滚动日志时连是连不上的，等出现监听端口的提示再说。
3. **控制台只有一个窗口。** `serverconfig.xml` 格式错误，多半是标签没闭合或者值里带了非法字符。
4. **服务端日志正常但连不上。** 回到端口那一节，安全组和系统防火墙都检查一遍。
5. **能连上但进去就掉。** 内存不够，看服务端日志里有没有被强制终止的记录，考虑加 swap 或升配。

管理权限建议先在服务器本机用 `telnet 127.0.0.1 8081` 给自己开，命令是 `admin add <玩家名> 0`，0 是最高权限。之后在游戏里按 F1 就能直接用 `give`、`ban`、`say` 这些指令了。远程 telnet 需要先在配置文件里设好 `TelnetPassword`，否则连不上。

## 存档、备份和 Mod，开服之后迟早要面对

存档位置随系统不同。Linux 下默认在 `~/.local/share/7DaysToDie/Saves`，Windows 下如果在配置文件里指定了 `UserDataFolder`，就在你指定的那个目录里。备份的做法就是把整个存档文件夹复制走，关服状态下复制，别在服务端运行时操作。

想把单人存档搬到服务器上，步骤是：先在服务器上配好存档路径并启动一次，让它生成目录结构；关服；把本地 `%appdata%\7DaysToDie\Saves` 下对应的文件夹整个复制过去；然后在 `serverconfig.xml` 里把 `GameWorld`、`WorldGenSize`、`GameName` 三项改成和存档一致；再启动，存档就继承过来了。这三项对不上，服务器会当成新世界重新生成。

装 Mod 的前提是两边都关 EAC。服务端改 `EACEnabled` 为 `false`；客户端在 Steam 里右键七日杀 → 属性 → 启动项选“在开始游戏时询问”，下次启动时在弹出的窗口里取消勾选 EAC 再进游戏。服务端和客户端装的 Mod 必须完全一致，版本不一致会导致进不去或者进去之后行为诡异。判断有没有生效，看服务端启动日志里 Mod 加载那一行的颜色，不是绿色基本就是没加载成功。

## 常见问题

**2 核 4G 真的够吗？**
3～5 人玩原版够用。人再多，或者打算装超过两三个 Mod、把地图尺寸调大，就上 4 核 8G，别硬撑。

**开服需要再买一份游戏吗？**
服务端用 SteamCMD 的匿名账号就能下载，不需要额外购买。客户端这边需要正版游戏才能连。

**服务器重启后要手动再开一次吗？**
要。SteamCMD 拉下来的服务端不会自动注册成系统服务，重启机器后得重新执行启动脚本。想省事可以自己写一个 systemd 服务或者 Windows 计划任务。

**能不能几个人共用一个服务器开多个存档？**
可以，但每个实例要占独立端口和独立内存，2 核 4G 的机器同时跑两个实例基本会卡。分开买两台更省心。

**服务端怎么更新？**
重新执行一次 `app_update 294420 validate` 就行，下载命令和安装时是同一条。更新前记得备份存档。
